[原题与附件](PROMPT.md) · [官方题解](https://ctf.rarebytehub.com/events/mimic/writeups/official-solution-the-keeper-of-salt-reach)

附件是一个没有扩展名的 `logbook`，`file` 的识别能力取决于本机 magic 数据库；它实际是 Python 3.12 的字节码——开头四个字节 `cb 0d 0d 0a` 就是 pyc 的 magic。

处理方式是静态的：跳过 16 字节 pyc 头，用 `marshal` 解析代码对象，只读常量，不执行也不导入题目模块。注意解释器版本必须匹配，这里应使用 Python 3.12 来匹配代码对象布局和指令语义。

## 参数全在常量里

代码常量中有两样关键东西：

- `Q`：560 个十六进制字符，即 280 字节
- `N = 35`

种子也不是外部给的。嵌套函数 `_t` 的原始 `co_code` 做一次 SHA-256，取前四字节按大端转成 32 位初始种子——**种子来自字节码自身**，这说明换一个编译产物就解不开。

反汇编中的 `gettrace` 分支会在追踪启用时把种子 XOR `0x5a5a5a5a`。普通种子是 `0x23ba3afa`，追踪分支种子为 `0x79e060a0`。静态解析采用普通种子，无需执行该分支。

## 分组结构

第 i 组的密钥：

```text
SHA256(seed_be32 || byte(i))[:8]
```

每组八字节，XOR 解密后按固定规则验证：

```text
(sum(block[:7]) * 31 + 7) & 255 == block[7]
```

按零起始偏移，字节 0..5 是三对操作码和参数，字节 6 是目标值，字节 7 是校验字节。

## 每个字节都是被约束出来的

原始操作码有四个，含义分别是：

| 操作码 | 运算 |
|---|---|
| 60 | 模 256 加法 |
| 161 | XOR |
| 87 | 循环左移 |
| 233 | 乘以 `(k \| 1)` |

这个映射来自字节码分析，不是从目标字符串反推的——也可以按逆序进行解析求逆：加法改减法，XOR 再做一次，左旋改右旋，奇数乘法改乘模逆元。

每组枚举 0 到 255，依次做三个操作再和目标比较。每组**恰好只有一个**候选，这有结构上的原因：加法、XOR、循环移位都是双射，模 256 乘奇数也可逆，所以它们的复合变换对每个目标恰有一个原像。

解完一组要更新种子：

```text
seed = (seed * 131 + block[6] * 257 + i + 1) mod 2^32
```

这里有个关键顺序：更新用的是**解密后的目标字节**，不是原始密文。如果拿初始种子独立去解所有分组，第一组之后全部错位。

```text
RBH{th3_l1ght_w4s_n3v3r_l1t_4t_4ll}
```

## 校验

35 个分组的校验字节全部通过，35 个字节候选全部唯一。枚举规模约 35 × 256 × 3 次运算——不需要执行原来的 `_v()`。

文件里还有一些看起来像提示的字符串，是诱饵，不参与任何计算。
